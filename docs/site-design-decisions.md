# 海外留学生の就活情報サイト：デザインの決定事項

最終更新：2026-11-17
デザインは Google Stitch、実装は Claude Code（Next.js＋Tailwind、静的書き出し）。写真は Unsplash（ダウンロードして public/images/）。
実装するときは、このファイルを仕様として読むこと。

## 読者とカテゴリ
- 読者：海外の大学で学ぶ日本人留学生（就活中・準備中）
- 大カテゴリ4つ：ボスキャリ／就活タイムライン／求人・就職情報／応募・面接（中カテゴリと記事は wiki の構成どおり。並び順は下の「記事の並び順」）

## ページの階層と分類
- ページは3段：トップ → カテゴリ → 記事。URL は /ja/{カテゴリ}/{記事}/（例：/ja/selection/self-pr/）
- 中カテゴリ（応募準備・質問対策など）は独立したページにしない。カテゴリページの中の見出しとして使う
- パンくずは「ホーム › カテゴリ › 中カテゴリ › 記事」と表示し、中カテゴリはカテゴリページのその見出しへのリンク（#{中カテゴリ}）
- 分類の仕方は、当面はトップページの「カテゴリから探す」と、記事の「前の記事／次の記事」の順番で見せる
- カテゴリページ：シンプルな記事一覧をデータから自動で作る（デザイン画像は作らない）。上に中カテゴリのピル（見出しへ移動）、見出しごとに記事カード。中カテゴリが1つだけのカテゴリ（就活タイムライン）は見出しを出さない。ボスキャリは自分の記事と「人気のページ」（紹介）を分けて並べる
- 将来カテゴリを増やすとき（9カテゴリの構想：Ryugaku Prep／Housing & Daily Life／Academics／University Guides／Shukatsu Timeline／Job Search Channels／Applications & Interviews／Visas After Graduation／Glossary）：ページの段は増やさず、ヘッダーのメニューで「留学・生活」「就活」のようにグループにまとめる。ボスキャリはカテゴリではなく「特集」に移すのがよい。ただし9カテゴリ構想は日本に来る外国人留学生向けの内容が中心なので、読者をどう分けるか（下の未決定）を先に決める

## トップページ（上から順）
1. ヘッダー：［サイト名］（テキスト）、カテゴリ4つ、検索、言語切替。ログインアイコンは置かない
2. ヒーロー：写真、キャッチコピー「海外留学生の就活を、ここからはじめよう。」、検索窓、よく検索されるキーワード
3. カテゴリから探す：左に縦タブ（4カテゴリ）、右のパネルに中カテゴリのピルと記事一覧。タブで切り替わる（ページ移動なし。スマホではタブを横スクロールのピルに）。「（カテゴリ名）の記事をもっと見る」はカテゴリページへ
4. イベント：バナー1枚＋キャリアフォーラムのピル（下の「イベント」）
5. よく読まれている記事：4カテゴリから6本（仮：Growth Mind Set、面接対策、ビジネス系の就活タイムライン、各国主要プラットフォーム、自己PR、SPI）。記事データの popular の番号順
6. フッター：［サイト名］、カテゴリ4つ、運営者情報、お問い合わせ・誤りの報告、プライバシーポリシー

比較用のパターン：A＝イベントなし／B＝A＋イベント（標準案）／C＝B＋ヒーローに「初めての方へ →」（中身は /ja/about）。現在の画像は C。「初めての方へ」のページの中身ができるまでは、ボタンを出さないか仮ページにする

### イベント
- 目的：イベント情報はこのサイトで書かず、主催者のページやフォーラム記事へつなぐ（追加の記事を作らない。日程が古くならない）
- 上段：横長のバナー1枚（写真を背景に、左に文字）
  - ラベル「グロキャリ主催」、見出し「グロキャリのイベント・説明会」、説明文「留学生の就活に役立つイベントを開催しています」
  - ボタン「イベント情報を見る ↗」→ グロキャリのイベントページ（外部、URL 未定。決まるまでは #）
- 下段：小見出し「キャリアフォーラムの情報」と、ピル型のリンク（ボストン（ボスキャリ）／ロンドン／ロサンゼルス／TKF／国内開催）→ それぞれこのサイトのフォーラム記事
- 日付・会場・開催時期は表示しない
- 外部リンクは「↗」の印をつけ、別タブで開く
- データは src/data/events.ts（バナーの文言・写真・リンク先、フォーラムのピルの名前とリンク先）
- イベントやフォーラムが増えたら、写真つきカードの横スライド（自動では動かさない、scroll-snap）に切り替える案もある

## 記事ページ（上から順）
1. パンくず、最終確認日のブロック、タイトル、タグ（カテゴリ・中カテゴリ）、更新日
2. アイキャッチ写真、導入文
3. 目次（番号つき・開閉式）。PC は右サイドバーにも付いてくる目次
4. 本文：wiki の内容を部品に置き換える（ステップ、NG／こうする、例文カード、チェックリスト、基本情報カード、タイムライン）。中身は足さない
5. 出典（＋wiki をもとに作成した旨の一文：出所表示の方針は未決定）
6. 記事の誤りを報告する（箱。ボタンの行き先は Google フォーム予定。記事名と URL を自動で入れる）
7. 前の記事／次の記事（下の「前の記事／次の記事」）
8. 関連記事：記事データの related に手で指定した3本。前後の記事とは重ねない
9. 右サイドバー：人気記事（順位つき）、カテゴリー、記事の目次
- SNS 共有ボタンは置かない

### 前の記事／次の記事
- 役割：同じ大カテゴリの記事を、1本目から最後まで順番に読み進めるため
- 順番：下の「記事の並び順」で、そのカテゴリの記事を1列に並べた順
- 表示：左に「← 前の記事」とタイトル、右に「次の記事 →」とタイトル。スマホでは縦に2段
- 1本目の記事の「前」と、最後の記事の「次」には、「（カテゴリ名）の記事一覧へ」のカードを出す（空欄にしない）
- 自動で作る：記事を書く人が前後を指定する必要はない

### 記事の並び順
- 1つの記事が属する（ホームの）カテゴリは1つだけ。パンくずと前後の記事は、ホームのカテゴリの順番で決める
- ほかのカテゴリにも並べたい記事（例：ボスキャリの「人気のページ」）は「紹介」として表示するだけで、そのカテゴリの前後の順番には入れない
- 順番は番号ではなく、src/data/ のカテゴリのデータに書いた並び順（中カテゴリの順 → その中の記事の順）で持つ。記事を足すときは、入れたい位置に1行足すだけ
- 中カテゴリの入口になる記事（応募準備・選考試験・面接対策）は、その中カテゴリの先頭に置く
- 現在の並び（wiki の目次の順）：
  - 応募・面接（22本）：応募準備 → 自己分析 → ES → 履歴書 → 選考試験 → SPI → 玉手箱 → TG-WEB → コーディングテスト → 面接対策 → STARストーリー → 自己紹介 → ガクチカ → 自己PR → 長所短所 → 志望動機 → グループディスカッション → 集団面接 → ケース面接 → テクニカル面接 → マナー・服装 → 直前・当日リマインド
  - 就活タイムライン（3本）：アート系 → ビジネス系 → 工学系
  - 求人・就職情報（11本）：LinkedIn → 各国主要プラットフォーム → 国内開催フォーラム → ロサンゼルスキャリアフォーラム → ロンドンキャリアフォーラム → TKF → Alphaアドバイザー → キャリアアカデミー → LinkedIn Student Club → Sekaia → 金融経済アカデミー

## 守るルール
- 「公式」「公認」など、公的機関だと誤解させる言葉は使わない
- 日付・数字・年・出典は作らない（［日付］［確認後に入れます］）
- グラデーション、絵文字、文字を重ねた YouTube 風サムネイルは使わない
- AI 生成画像は人物・実在の場所に使わない
- 自動で動くスライドショーは使わない
